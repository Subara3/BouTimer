作業のおとも、棒人間　フレンド（ゴースト）

ゴースト置き場のしくみ

休憩になると、ほかの人の棒人間が半透明で遊びに来ます。その記録を預かっているのが、Cloudflare Workersで動く小さなサーバーです。アプリからサーバーまでの流れと、無料で公開しても止まりにくくするための工夫をまとめました。

1全体の流れ

登場するのは3つだけです。アプリ（HSP）、Cloudflare Workersの上で動くJavaScript、データを置くWorkers KVです。アプリは、設定の「サーバーと通信する（ゴースト機能用）」がオンのときだけ通信します。最初はオフです。

sequenceDiagram
  participant A as アプリ（HSP・hspinet）
  participant W as Workers（boutimer-ghost）
  participant K as KV（キー "recent" 1件）
  Note over A: ポモドーロを1つ終えて休憩に入る
  A->>W: POST /ghost（id・線の色・数字）
  W->>K: get "recent"（最新を読む）
  W->>K: put "recent"（自分の分を先頭に入れて保存）
  W-->>A: ok
  A->>W: GET /ghosts?n=1&me=自分のid
  W->>K: get "recent"
  W-->>A: 1人分の数字（id は外す）
  Note over A: ゴーストが降ってきて、十数秒あいさつして帰る

送る（POST）のと受け取る（GET）のは、ポモドーロを1つ終えたときと、「サーバーと通信する」をオンにしたときです。休憩のたびに1回ずつなので、1人が1日に通信するのは十数回くらいになります。

2送るもの・受け取るもの

送るもの（POST /ghost）

id=3f9a0c12b7e45d68&c=3026486&p=3&m=75&f=4
  id  はじめて起動したときに作る16桁の16進（settings.txt に保存）
  c   線の色（RGB を10進で）
  p   今日のポモドーロ数（0〜99）
  m   今日の作業分数（0〜1440）
  f   よくやった動きの番号（お茶・読書・ダンス・腕立て・ほうき）

名前、アプリ名、ウィンドウのタイトル、キー入力は送りません。サーバーも数字以外を受け付けない作りなので、文字を書きこまれることがありません。

受け取るもの（GET /ghosts）

2763306,4,100,3,0
  色, ポモドーロ数, 作業分数, 動きの番号, 見本なら1

直近24時間に送ってきた人の中から、自分以外をランダムに選んで返します。idは返さないので、受け取った側には誰のゴーストかわかりません。参加者がまだいないときは、色と数字を決めておいた見本のゴースト（最後が1）を返します。

3Cloudflare WorkersとKV

Cloudflare Workersは、Cloudflareの世界中の拠点でJavaScriptを動かすサービスです。サーバーを借りたり起動しておいたりする必要がなく、リクエストが来たときだけfetch(req, env)が呼ばれます。Workers KVは、そこから読み書きできるキーと値の置き場です。

無料枠でできること上限このアプリでの使い方
Workersのリクエスト10万回/日送ると受け取るで、1回の休憩に2回
KVの読み出し10万回/日送るときと受け取るときに1回ずつ
KVの書きこみ1,000回/日送るときだけ。いちばん先に足りなくなる
同じキーへの書きこみ1回/秒キーは1つなので、全員の書きこみがここに集まる

KVには、キーrecentの1件だけを置いています。中身は最大60人・24時間分の配列です。1人1キーにすると、書きこみのほかに一覧を取るための読み出しも増えるので、1件にまとめました。

[
  { "id": "3f9a0c12b7e45d68", "c": 3026486, "p": 3, "m": 75, "f": 4, "t": 1792134620909 },
  { "id": "a1b2c3d4e5f60718", "c": 255, "p": 2, "m": 50, "f": 3, "t": 1792134584426 }
]
  t はサーバーが受け取った時刻（ミリ秒）。24時間たった人は、次の書きこみのときに消える

4公開しても止まりにくくするために

いちばん困るのは、書きこみの無料枠（1日1,000回）を使い切られて、その日は全員のゴーストが来なくなることです。そのため、書きこむ前に次の6つを確かめています。

同じIPからは1分に1回送ってきたIPをハッシュにして、CloudflareのCache APIに1分だけ印を置きます。印があれば書きこまずにokを返します。IPそのものはどこにも保存しません。
変わっていなければ書かない同じidが10分以内に同じ数字を送ってきたときは、書きこみを省きます。
書く前に最新を読むキャッシュした古い一覧に上書きすると、直前に書いた人の分が消えます。書きこみの前は、キャッシュを使わずに読みます。
失敗しても200を返す無料枠を使い切ったときや、1秒に2回書こうとしたときは、エラーにせず「busy」を返します。アプリ側は何もせず、ゴーストが来ないだけで済みます。
数字だけ・短いものだけidは16桁の16進だけを通します（それ以外は400）。本文が200文字をこえたら413。数字は上限で切りそろえます（ポモドーロ99、分数1440）。
アプリも返事を確かめる返ってきた行が数字とカンマだけのときだけゴーストを出します。エラーページが返ってきても、変なゴーストは出ません。

5アプリ側（HSP）

通信はHSP付属のhspinetプラグインで行います。netrequest_postやnetrequest_getで頼んでおき、メインループで毎フレームnetexecを呼んで終わったかを見ます。待っているあいだも棒人間は止まりません。

neturl gh_url
netheader "Content-Type: application/x-www-form-urlencoded\n"
netrequest_post "ghost", gbody     ; 頼むだけで、すぐ戻ってくる
...
netexec gres                       ; 毎フレーム。0 ならまだ、1 なら完了、負なら失敗
if gres > 0 : netgetv gtxt         ; 返事を受け取る

ゴーストは本体とは別の小さな窓に半透明で描いています。クリックは下の窓へ素通りし、足場にもなりません。

6フレンド（特定の人とだけ見せあう）

知らない人ではなく、友だちの棒人間を呼ぶには？

アプリが最初に作る匿名のIDから、サーバーがSHA-256で8文字のフレンドコードを作ります。読みまちがえやすいI・L・O・Uは使いません。IDそのものは送り返さないので、コードからIDはたどれません。

おたがいに相手のコードを登録したときだけ、サイクル数などの数字が見えます。片方だけが登録しているあいだは「相手の登録待ち」、コードがないときは「見つからない」と返します。メッセージを送る機能はありません。

フレンドの通信は、Windows 10 1803以降に入っているcurl.exeを窓なしで起動して行います。返事はファイルで受け取り、メインループで終わったかを見ます。hspinetで受け取ると、そのあいだメインループが数秒止まって、棒人間がつかめなくなったためです。休憩に入るときにフレンドがいれば、知らない人より先にフレンドのゴーストを呼びます。

7置き場を更新するとき

サーバーのコードはserver/src/index.jsの1ファイルだけで、設定はwrangler.tomlに書いています。Cloudflareの公式ツールwranglerで、ログインしてからwrangler deployを実行すると、数秒で全世界の拠点に切りかわります。このフォルダは日本語のパスなので、ASCIIだけのフォルダにコピーしてから実行しています。

name = "boutimer-ghost"
main = "src/index.js"

[[kv_namespaces]]
binding = "GHOSTS"                      ; コードからは env.GHOSTS で使う
id = "dd685ae107894f9b825f39171bdf5527"

公開先はhttps://boutimer-ghost.subara3.workers.devです。配った版のアプリはこの住所に送るので、変えるとそれまでの版からはつながらなくなります。

8わかっている限界

  • 2人がほぼ同時（1秒以内）に送ると、片方の分が一覧に残らないことがあります。KVは「読んでから書く」を1つの手順として守ってくれないためです。次の休憩でまた送るので、次の回には戻ります。
  • KVは世界中の拠点に行きわたるまで最大60秒ほどかかります。送った直後に別の拠点から読むと、まだ載っていないことがあります。
  • 同じ会社などで同じIPを使っている人は、1分以内に2人目が送ると、その回は記録されません。
  • 書きこみの無料枠を使い切った日は、新しく送った分が載りません。それまでの人のゴーストはそのまま届きます。

どの場合も、困るのは「ゴーストが来ない」ことだけです。タイマーやほかの機能は、通信がなくてもふつうに動きます。
