作業のおとも、棒人間　技術解説

棒人間が動くしくみ

デスクトップのウィンドウの上を歩いて、お茶を飲んで、休憩になると使っている窓のふちに座る。やることリストを管理してくれる、ポモドーロタイマーの棒人間はどうやって動いているのでしょうか？

601秒に回すメインループの回数
24動き（お茶・釣り・縄跳びなど）
25状態（歩く・寝る・のぞくなど）
29ソースのファイル数
メインループ窓の上に立つ透ける絵体の動かし方跳ぶ・落ちる道さがし窓ごとの性格線の色音楽打つ・離席文字カーソル声と口パク全画面と電池絵日記ゴーストはじめての起動

01メインループ

どうやって動いてるの？

起動すると、1つのループを1秒に60回まわします。1回ごとに、タイマーを進め、入力と音を見て、乗っている窓を確かめ、何をするか決め、体を動かし、絵を描きます。最後にawait 16で16ミリ秒休んで、また頭に戻る、のくり返しです。

*mainloop
    gosub *tick_timer      ; ポモドーロの残り時間
    gosub *watch_input     ; 打った回数・離席
    gosub *listen          ; 音楽の音量
    gosub *poll_mouse      ; つつく・つまむ・なでる
    gosub *brain           ; 次に何をするか
    gosub *fall            ; 重力と着地
    gosub *render          ; 絵を描いて画面へ
    await 16
    goto *mainloop

止まっているときは描く回数を半分（30回）に落として、CPUを使いすぎないようにしています。ソースは機能ごとに29のファイルに分け、main.hspから#includeで読みこんでいます。

02窓の上に立つ

どうしてウィンドウの上を歩けるの？

画面の手前から奥へ、開いているウィンドウを順にたどって、上の辺を「足場」の一覧にしています（GetTopWindowとGetWindow）。見えない窓、最小化した窓、最大化した窓、小さすぎる窓は外します。

  • 窓の位置はDwmGetWindowAttributeで取ります。Windows 11のGetWindowRectは見えない影の分だけ外に広く、そのまま使うと宙に浮いて見えるためです。
  • 裏で隠れているストアアプリ（DWMWA_CLOAKED）は、見えていなくても一覧に出てくるので外します。
  • 手前の別の窓に隠れている辺には立ちません。着地点のすぐ下をWindowFromPointで調べて、本当にその窓が見えているかを確かめます。

乗っている窓を毎フレーム調べなおして、窓が動いたら同じだけ一緒に動きます。左右に揺さぶられたら目を回して落ちるし、窓が閉じたら「おっと」と言って落ちます。

03透ける絵を描く

背景はどうやって透かしてるの？

棒人間は、220×140の小さなウィンドウに描いています。このウィンドウにWS_EX_LAYEREDを付けて、32ビットの画像をUpdateLayeredWindowで画面に貼ると、画素ごとに透け具合を変えられます。決まった色を透明にする方法だと、線のふちのにじみが汚く残るので、この方法にしました。

絵はGDI+でその画像に描きます。白い太い線（ふちどり）で1回、黒い線で1回の、2回描くと、どんな色の窓の上でも棒人間が読めます。吹き出しの文字は、同じ文字なら前に作った画像を貼るだけにして、毎回の文字描きを省いています。

HSPには、小数をGDI+のfloatの並びに直す命令がありません。四角の位置を渡すために、指数と仮数を計算する関数fbits()を自分で書いています。

04体の動かし方

どうやってポーズを作ってるの？

体は、腰・首・頭と、腕2本・脚2本でできています。腕と脚は、付け根の角度と、ひじ・ひざから先の角度の2つで決まります（真下が0度、前が正）。ポーズを作る処理は、状態と動きごとに、この角度を決めるだけです。

描くときは、腰の位置から順に線を引いていきます。ポーズを角度だけで持っているので、腕の長さや線の太さを変えても、全部のポーズがそのままついてきます。動きは24、状態は25です。

05跳ぶ・落ちる

ねらった窓にどうやって着地してるの？

重力は、1フレームごとに下向きの速さを0.5ピクセルずつ増やす加速です。跳ぶときは、着地したい点から逆算して、最初の速さを決めます。

頂点の高さ = 足もとと着地点の高いほう − 40
上向きの速さ vy = −√(2 × 重力 × (足もと − 頂点))
かかる時間 t = 上がる時間 + 頂点から着地点まで落ちる時間
横の速さ vx = 横の距離 ÷ t

落ちている途中は、足が足場の辺を上から下へ横切ったフレームで着地します。投げられたときは、見えている窓の横の辺や画面の端で跳ね返ります。窓の縁のそばで離すと、縁につかまってよじ登ります。

06窓を渡って行く道さがし

ダブルクリックしたところまで、どうやって来るの？

窓の上の辺のうち、見えているいちばん長い区間を「ノード」にして、地面も1つのノードにします。2つのノードのあいだは、横のすき間が380ピクセル以内で、上へ跳ぶなら高さの差が330ピクセル以内のとき、跳べることにして、その距離に1回跳ぶぶんの60を足した値を「かかる手間」にします。

いまいるノードからゴールまで、手間がいちばん小さい道を探す方法は、ダイクストラ法です。窓が動いたり閉じたりしたら、その場で探しなおします。文字カーソルをのぞきに行くときだけは、道がなければ大ジャンプで飛び乗ります。

07窓ごとに性格が変わる

窓によって遊び方が変わるのは？

乗っている窓のクラス名とタイトルの文字から、ハッシュという数を作っています（1文字ずつ「33倍して足す」を繰り返す、djb2という方法）。この数を乱数の種にして、どの動きをどの順でやるか、拾った棒を剣にするか釣り竿にするか、を決めます。

同じ窓の上では同じ種から選ぶので、ある窓では読書が多く、別の窓では縄跳びが多い、のように窓ごとにくせが出ます。タイトルは計算に使うだけで、どこにも残しません。

08線の色を窓のアイコンから

線の色はどこから来てるの？

線の色が「おまかせ」のとき、乗っている窓のアイコンを取り出して（WM_GETICON）、32×32の画像に描きます。その画素のうち、鮮やかな色ほど重みを大きくして平均し、いちばん明るい成分が110になるまで暗くして、線の色にします。

同じしくみで、見えている窓のアイコンを4つまで借りて遊びます。アイコンでリフティングやお手玉をしたり、1つずつ投げて積み上げたりします。積んだアイコンは、上の段ほど大きく揺れてから、回りながら崩れます。回して描くときは、GdipTranslateWorldTransformとGdipRotateWorldTransformでアイコンの中心に座標を移して回し、描いたあとに逆の順で戻しています。

「PCのようす」は、Windowsが数だけを返す関数を読んでいます。CPUの使用率はGetSystemTimesのアイドル・カーネル・ユーザーの時間の1秒ぶんの差から、メモリはGlobalMemoryStatusEx、ディスクの空きはGetDiskFreeSpaceExW、ゴミ箱の数はSHQueryRecycleBinW、PCをつけてからの時間はGetTickCount64です。64bitの値は、HSPの32bitの整数を2つ並べて受け取り、小数で組み立てます。マウスの距離は、毎フレームのカーソルの移動を、モニターの実寸（GetDeviceCapsのHORZSIZE÷HORZRES）でミリメートルに直して足しています。

色は一度に変えず、毎フレーム少しずつ目標の色へ寄せています。窓を移ると、じわっと色が変わるのはそのためです。

09音楽に合わせて動く

曲がかかっているのが、どうしてわかるの？

WindowsのCore AudioにあるIAudioMeterInformationをCOMで呼び、いまスピーカーから出ている音の大きさ（ピークの値）だけを毎フレーム読みます。録音はしないので、何の音かはわかりません。

ならした音量 = ならした音量 × 0.96 + いまの音量 × 0.04
拍とみなす：いまの音量 > ならした音量 × 1.35、かつ前の拍から 15フレーム以上
曲とみなす：ならした音量 > 0.02 が3秒くらい続いた

曲とみなすと、拍に合わせて体を弾ませてノリはじめ、音が止まると「いい曲だった」と言います。

10打つ速さと離席

速く打つと、なんで一緒に打ちはじめるの？

キーは「押された瞬間の回数」だけを数えます。どのキーかは変数にも残しません。最後に操作した時刻（GetLastInputInfo）が変わったフレームだけキーの状態を読むので、何もしていないあいだは調べることもしません。

打った回数を、毎フレーム0.98倍しながら足していった値を「打つ速さ」にして、速いと小さなノートパソコンを出して一緒に打ちます。5分操作がないと「おーい、どこ行った～？」などと呼び、10分ないとタイマーを止めて寝て待ちます。絵を描いているときなど止めてほしくない人のために、止めない設定もあります。

カーソルが棒人間に重なっているあいだは、つまみやすいように、その場で立ち止まります。重なっているかは、描いた絵のその画素が透明かどうかで決めています。

11文字カーソルをのぞきに来る

打っているところに、どうやって来るの？

GetGUIThreadInfoに0を渡すと、手前の窓の文字カーソルの位置が返ってきます。位置だけを読んで、打った文字や画面の中身は読みません。カーソルがよく動いているあいだ（動いた回数を0.93倍しながら数えて6をこえたら）、その窓の上まで道を探して行き、前かがみでのぞきこみます。5分に1回までです。

ChromeやVS Codeのように、Windows標準の文字カーソルを使わないアプリでは、位置が取れないので来ません。

12声と口パク

口の動きを声に合わせるには？

声は、決まった文のセリフをVOICEVOX（玄野武宏）で前もって作り、voiceフォルダに入れてあります。ファイル名は、セリフのUTF-8のバイト列から作るハッシュ（djb2）です。アプリも同じ計算をするので、吹き出しの文からファイルを探せます。数字の入るセリフは「3個目！やったな」の「やったな」のように、決まった部分だけを声にします。

声を作るときにaudio_queryの答え（1音ごとの子音と母音の長さのJSON）も一緒に残しておきます。これを読んで「何秒後に、あ・い・う・え・おのどの口にするか」の表を作り、再生を始めた時刻に合わせて口の形を切りかえます。

wavは16kHzのIMA ADPCMにして、全部で約2.0MBです。メモリに読んでPlaySound（SND_MEMORY）で鳴らします。効果音はMCI（mciSendString）で鳴らすので、声と重なっても止めあいません。

13全画面と電池

ゲームやプレゼンの最中は？

SHQueryUserNotificationStateで、全画面のアプリやプレゼンの最中かがわかります。その間は棒人間もゴーストも隠れて、声も出しません。

ノートPCが電池で動いているときや省電力モードのとき（GetSystemPowerStatus）は、描く回数をさらに減らします。測った範囲では、12秒あたりのCPU時間が0.92秒から0.39秒になりました。

14絵日記

絵日記はどうやって描いてるの？

日付が変わると、前の日の記録から640×500の絵日記を描いてPNGで保存します。画面には出さない画像にGDI+で描き、GdipSaveImageToFileで書き出しています。

日付の文字から乱数の種を作るので、同じ日なら何度描いても同じ絵日記です。空は5通り、場面は21通りあり、その日にあった出来事（釣った・こぼした・紙飛行機を飛ばした など）から場面と文を選びます。

15ゴースト

ほかの人の棒人間はどこから来るの？

「サーバーと通信する（ゴースト機能用）」をオンにすると、ポモドーロを1つ終えるたびに、匿名のIDと数字だけをCloudflare Workersに送り、ほかの人の数字を1人分もらいます。もらった数字から、同じ描き方で半透明の棒人間を描きます。くわしくは別の解説「ゴースト置き場のしくみ」にまとめています。

16着せ替え（珠音のドット絵）

ドット絵がにじまないのは？

着せ替えで珠音を選ぶと、棒人間の代わりに、HSP3のオフィシャル素材のドット絵（tamadot.png）を描きます。1枚の画像に64×64ドットのコマが8×8並んでいるので、向きと状態から行と列を選び、GdipDrawImageRectRectIでそのコマだけを切り出して描きます。右を向くときは、左向きのコマを左右反転して使います。

画面の拡大率が100%でないときもドットがにじまないように、描くあいだだけGdipSetInterpolationModeでいちばん近い画素を使う設定にし、GdipSetPixelOffsetModeで画素の中心をそろえています。

17はじめての起動

最初の質問の窓に、どうやって入ってるの？

はじめて起動したときは、メインループに入る前に質問の窓を開き、棒人間をその窓の床の位置に置きます。窓の中の座標をClientToScreenで画面の座標に直して、そこへ棒人間の窓を重ねています。

窓をドラッグしているあいだはメインループが止まるので、窓が動いたという知らせ（WM_MOVE）をoncmdで受けて、その場で棒人間を動かします。答え終わったら、上向きの速さを与えて、窓から外へ飛び出させます。
